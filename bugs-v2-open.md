#### OPEN-W1 подробно: fewer-braces `f(args): p =>` — репро и гипотеза фикса

> **ГИПОТЕЗА НИЖЕ ОПРОВЕРГНУТА ИЗМЕРЕНИЕМ 2026-07-28** (`v2-front-fewer-braces-and-lib-variants`).
> Дыра **не в layout-проходе**, а в **парсере**, поэтому правка `declColon` ничего не даёт —
> проверено, а не рассуждением: снял требование `inDeclHead` в ОБОИХ фронтах, пересобрал, репро
> падает по-прежнему (риск-кейсы `val x: Int = 5` и `case class P(a: Int):` при этом чисты, то
> есть правка безвредна — но и бесполезна). Откатил.
>
> **Что показывает IR** (`java -jar <kernel> run v2/bin/ssc1-run.ssc0 fb.ssc`, метод из передачи —
> он сработал и здесь):
>
> ```
> (def useColon (lam 0
>   (let ((app (global ap) (lit (int 3))))          <- ap(3) как отдельный statement
>     (let ((app (global _err) (global i)))          <- `: (i)` стало _err(i)
>       (app (global _err) (lam 0 … i * 2 …))))))    <- тело-лямбда тоже под _err
> ```
>
> Layout-проход отработал ПРАВИЛЬНО: `=>` уже layout-opener, поэтому тело `i * 2` собралось в
> `(lam 0 …)`. Сломано то, что **`:` вообще не потребляется как ввод trailing-аргумента** —
> `postfix` в F (`specs/v2.2-p6.5-fsub.ssc:539`) знает ветки `.`(31), `match`(5), `(`(21),
> `{`(28 → `postBlockArg`), и не знает `:`(34).
>
> **Направление фикса (уточнённое).** Добавить в `postfix` ветку на `:`(34), которая потребляет
> следующее выражение как ЕДИНСТВЕННЫЙ аргумент — к моменту разбора это уже готовая лямбда
> `(i) => { i * 2 }`, потому что layout свою часть сделал. Обязателен guard: срабатывать только
> когда за `:` идёт ЛЯМБДА (лоокахед на `(…) =>` или `id =>`), иначе ветка съест аскрипцию типа и
> двоеточие тела декларации. Оба фронта: F `postfix`, ssc1-front — ветка рядом с
> `trailing block argument: e { body } → e(body)` (`:1487`).
>
> Оценка: не однострочник — нужен лоокахед-хелпер в обоих фронтах плюс F-фикспойнт. Кто возьмёт:
> репро на 9 строк ниже, IR выше, точные строки названы.



Репро на 9 строк (v1 печатает `6 / 6`, натив отвергает файл):

```scalascript
def ap(n: Int)(f: Int => Int): Int = f(n)

def useBrace(): Int = ap(3)((i) => i * 2)

def useColon(): Int =
  ap(3): (i) =>
    i * 2

println(useBrace())
println(useColon())
```

**Гипотеза (НЕ проверена — файлы фронтов были заняты живым клеймом).** В layout-проходе
`ssc1-front.ssc0` двоеточие уже умеет открывать блок, но только в голове декларации:

```
declColon = if #seq(k, ":") then (if inParenLike then false else inDeclHead) else false
```

Достаточно снять требование `inDeclHead` — то есть *любое* двоеточие вне скобок, оказавшееся
последним токеном строки, открывает layout-блок:

```
declColon = if #seq(k, ":") then (if inParenLike then false else true) else false
```

Почему этого может хватить целиком: `prevOpener` смотрят только на NL, поэтому `val x: Int = 5` и
`def f(x: Int): Int =` не затрагиваются — там после `:` на той же строке идёт тип. А виртуальную
`{ (i) => i*2 }` дальше подхватит уже существующий путь `buildPostfix`, ветка `{`: *"trailing block
argument: `e { body }` → `e(body)`, lambda-aware: `parseBlockArg` strips a `param =>` header"* —
это ровно нужная форма.

**Риск, который надо измерить:** двоеточие, которое честно завершает строку, но блоком не является
(например, перенос длинной сигнатуры после `:`). Гейты `v2.2-p6.5-fsub.sh --self` (173 кейса +
фикспойнт) и `v2.2-p6.5-semantic.sh check` (247 golden'ов) покажут это сразу.

**Обязательно ОБА фронта** — дифференциальный гейт сравнивает F и оракул.

**Метод, который работает** (применён 5 раз за день): скомпилировать файл через
`java -jar <kernel> run v2/bin/ssc1-run.ssc0 <file>`, найти `(global _err)` в выданном IR и прочитать
70 символов вокруг — это почти всегда называет конструкцию.

## 3. Отдельно: 77 SKIP — это НЕ провалы v2

В обновлённой заморозке 77 строк `* SKIP`. `SKIP` означает, что **INT-лейн — эталон — сам не смог
выполнить кейс** (`int-nonzero` / `int-timeout`), поэтому ни один лейн не сравнивался и v2 никто не
спрашивал. Это отдельный бэклог (в основном серверные и сетевые демо). Засчитывать их против v2
было бы неверно — но и оставлять «невидимыми» тоже: пока эталон не бежит, эти кейсы не проверяются
**ни на одном** лейне.

**Вопрос на будущее:** нужен ли отдельный проход «почему INT не может выполнить 77 кейсов»?

## 4. Метод, который стоит помнить

**v2 падает не исключением, а СЕНТИНЕЛОМ.** Отсутствующий член вычисляется в `Stub` и программа
идёт дальше с **exit 0** — так вели себя `Mirror.isProduct`, `Mirror.fromProduct` и `List.apply`, и
сентинел `isProduct` потом рулил `if`. **Любая инвентаризация v2 обязана сравнивать ВЫВОД с
INT-лейном; проверка кода возврата покажет эти случаи как успех.**

Второе: **исправлять надо ОБА фронта.** Дифференциальный гейт утверждает, что F и оракул
эквивалентны по выводу, поэтому односторонний фикс превращает двусторонний неверный ответ в
зарегистрированный DIVERGE. За день это правило сработало четырежды.
