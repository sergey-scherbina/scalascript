# TUI emitted Cargo dependencies, derived from the emitted source

Status: spec (2026-08-04)
Owner: `tui-cargo-deps-derived`
Affected backend: static `frontend/tui` (`TuiEmitter` → ratatui crate)
Defect: [`BUGS.md`](BUGS.md) `tui-cargo-deps-are-a-hand-maintained-disjunction`

## Goal

The emitted `Cargo.toml` must declare exactly the crates the emitted `main.rs` uses, **because it
was computed from that text** — not because someone kept two conditions in agreement.

## Baseline defect

`cargoToml(manifest, hasFetch, needsSerdeJson)` takes booleans computed at the call site from the
FEATURES known to use each crate:

```scala
val needsSerde = remoteTable || fetches.values.exists(_.headersId.isDefined)
```

That disjunction grew a term today (the headers path) and will grow another for `tui-fetch-post`,
whose body encoder reaches for the same crate. Every term is a chance to forget, and forgetting
produces **a crate that does not compile** — a failure the fast emitter tests cannot see, because a
string test asserts the generated Rust *contains* `serde_json::from_str` and never looks at the
manifest.

## Required behavior

The manifest is generated **after** `main.rs`, from its text:

| crate | declared iff the emitted source contains |
|---|---|
| `ureq` | `ureq::` |
| `serde_json` | `serde_json::` |

No feature-shaped condition survives at the call site. Adding a future emission that uses either
crate requires no change here and cannot desynchronise.

**Ordering constraint:** `mainRs` must be produced before `cargoToml`, which is a swap of two
existing statements, not new machinery.

**Not a widening.** The emitted text is generated by this same object from the same view, so
"contains `serde_json::`" is exact, not a heuristic over user input. A crate referenced only inside
a string literal in generated code would be a false positive; no emission does that today, and the
test below pins the negative case so one cannot appear silently.

## Verification

- a view with no fetch emits neither dependency;
- a fetch without headers emits `ureq` and **not** `serde_json`;
- a fetch with headers, and separately a `DataTable.Remote`, each emit both;
- the existing cargo smokes still build — that is what proves the derived manifest is *sufficient*,
  which a string assertion cannot.

Required gate: `scripts/sbtc 'frontendTui/test'`, including the cargo smoke when `cargo` is
available.

## Non-goals

- Deriving dependencies for other backends. The same class may exist there; this spec is one
  emitter, and a claim per emitter is cheaper to verify than one sweeping change.
- Version selection. `ureq = "2"` / `serde_json = "1"` stay as they are.
